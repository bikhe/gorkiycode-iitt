# AssistantAI — документация для frontend-разработчика

Всё, что нужно фронту для работы с backend: вход, диалог с ассистентом, голос (распознавание и озвучивание), ошибки, лимиты, и что поменять в текущем `web/`. Примеры ответов ниже сняты с работающего сервера.

---

## 0. Коротко: что обязательно сделать на фронте

| # | Что | Почему |
|---|---|---|
| 1 | Адрес API — **относительный**: `/api/assistant`, а не `http://127.0.0.1:8765/api/assistant` (`web/index.html:92`) | На сервере страница и API на одном домене; абсолютный localhost-адрес у пользователя никуда не ведёт |
| 2 | **Экран входа/регистрации** поверх `/api/register`, `/api/login`; кнопка «Выйти» → `/api/logout` | Без входа `/api/assistant`, `/api/transcribe`, `/api/tts` отвечают `401` |
| 3 | При старте: `GET /api/me` (вошёл ли) и `GET /api/config` (нужен ли вход, кто озвучивает) | Чтобы сразу показать нужный экран |
| 4 | Перестать слать `user_id` (сервер его игнорирует) и параметр `?user=` | Владелец записей определяется по сессии |
| 5 | Обработать `401` в любом запросе → показать экран входа | Сессия могла истечь (30 дней) или пользователь вышел в другой вкладке |
| 6 | Озвучка: если `config.tts === "google"` — играть аудио из `POST /api/tts`, иначе `speechSynthesis` как сейчас | Серверный TTS включается настройкой без правок фронта |
| 7 | Обновить тексты ошибок в `voice.js` (`_post`): там упоминаются `server.py` и `APP_API_TOKEN`, которых больше нет в схеме | Пользователь увидит неверную подсказку |

## 1. Запуск backend для разработки фронта

```powershell
.\.venv\Scripts\python.exe -m uvicorn fastapi_server:app --host 127.0.0.1 --port 8765 --reload
```

- Страница ассистента: **`http://127.0.0.1:8765/app/?stt=local`** (лендинг: `/`) — FastAPI сам раздаёт файлы из `web/`. Правки в `web/` видны после обновления страницы.
- Swagger со всеми маршрутами: `http://127.0.0.1:8765/docs`.
- Без ключа GigaChat: `APP_OFFLINE=1` в `.env` — простой разбор фраз без LLM, удобно для вёрстки.
- Пока экрана входа нет: `APP_AUTH_REQUIRED=0` в `.env` — вход не нужен, работает как раньше (`user_id` из тела).

> **Открывайте страницу с того же адреса, что и API.** `localhost` и `127.0.0.1` для браузера — разные сайты: cookie входа, выданная на `127.0.0.1:8765`, не уйдёт в запрос со страницы `localhost:5500`. Если всё же нужен отдельный dev-сервер (Vite и т.п.) — настройте в нём proxy `/api → http://127.0.0.1:8765`, тогда для браузера всё на одном адресе.

## 2. Общие правила запросов

- Все тела — JSON (`Content-Type: application/json`), кроме `/api/transcribe` (`multipart/form-data`).
- Ответ об ошибке: `{"detail": "<код>"}`; код — короткая строка для логики, **не для показа пользователю** (кроме 400 при регистрации, там `detail` — готовый русский текст).
- Авторизация — **cookie `assistant_session`** (HttpOnly, ставится сервером при входе). При запросах с той же страницы `fetch` отправляет её сам, ничего добавлять не нужно.
- Альтернатива cookie — заголовок `Authorization: Bearer <token>` (`token` приходит в ответе входа). Нужен только для не-браузерных клиентов или отдельного dev-сервера без proxy. **Не храните токен в `localStorage` без необходимости** — cookie надёжнее (недоступна JS).
- Запросы с чужого сайта отклоняются `403 origin_forbidden`. Разрешены: страница, раздаваемая этим же сервером, и адреса из `APP_CORS_ORIGIN`.

## 3. Вход и пользователи

### `POST /api/register`

```json
{ "username": "anna", "password": "secret-pass-1" }
```

Ответ `200` — пользователь создан и **сразу вошёл** (cookie уже установлена):

```json
{ "user": { "id": 1, "username": "anna" }, "token": "ZTF2Ej_XfEE..." }
```

| Код | `detail` | Показать |
|---|---|---|
| 400 | `Логин: 3–32 символа, латиница, цифры, _ . -` | текст из `detail` |
| 400 | `Пароль: от 8 до 128 символов` | текст из `detail` |
| 409 | `username_taken` | «Такой логин уже занят» |
| 403 | `registration_closed` | «Регистрация закрыта» |

Правила для подсказок в форме: логин `^[A-Za-z0-9_.\-]{3,32}$` (регистр не важен: `Anna` и `anna` — один пользователь), пароль 8–128 символов.

### `POST /api/login`

Тело то же. Ответ `200` — как у регистрации.

| Код | `detail` | Показать |
|---|---|---|
| 401 | `invalid_credentials` | «Неверный логин или пароль» (не уточнять, что именно) |
| 429 | `too_many_attempts` | «Слишком много попыток, подождите 5 минут» — после 10 неудач за 5 минут на IP + логин |

### `POST /api/logout`

Без тела. Ответ `{"ok": true}`, cookie удаляется. После — очистить историю диалога на экране и вызвать `newSession()` (см. §4.3).

### `GET /api/me`

`200` → `{"user": {"id": 1, "username": "anna"}}`, `401` → не вошёл.

### Пример

```js
async function api(path, body) {
  const res = await fetch(path, {
    method: body === undefined ? 'GET' : 'POST',
    headers: body === undefined ? {} : { 'Content-Type': 'application/json' },
    body: body === undefined ? undefined : JSON.stringify(body),
  });
  if (res.status === 401 && !path.startsWith('/api/login')) showLogin();
  return res;
}

// старт приложения
const config = await (await api('/api/config')).json();
const me = await api('/api/me');
if (config.auth_required && me.status === 401) showLogin(); else showChat();
```

## 4. Диалог с ассистентом

### 4.1. `POST /api/assistant`

```json
{
  "text": "Напомни мне завтра в 10 утра позвонить Ивану",
  "session_id": "8f0c…",
  "request_id": "b1e2…"
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `text` | да | Фраза пользователя (набранная или распознанная). Не пустая, до 8 КБ. |
| `session_id` | желательно | ID диалога, до 100 символов. **Одинаковый на весь разговор**: уточнения («в 12:00», «да», «2») понимаются только в той же сессии. По умолчанию `"browser"`. |
| `request_id` | желательно | Уникальный ID **этого** запроса (UUID), 1–120 символов. Повтор с тем же `request_id` вернёт сохранённый ответ и **не создаст запись второй раз** — так безопасно повторять запрос при обрыве сети. |
| `user_id` | нет | Игнорируется, если включён вход. Только для `APP_AUTH_REQUIRED=0`. |

Ответ всегда `200` с объектом (HTTP-ошибки — §7):

```json
{
  "status": "success",
  "action": "create",
  "display_text": "Напоминание создано: «Позвонить Ивану» — 28.10.2026 в 10:00.",
  "speech_text": "Готово! напоминание «Позвонить Ивану» создано. Дата: 28.10.2026 в 10:00.",
  "item": { "...": "запись, см. §4.4" }
}
```

| Поле | Всегда | Что делать |
|---|---|---|
| `status` | да | Определяет поведение UI — §4.2 |
| `display_text` | да | **Показать** в чате как есть. Может содержать `\n` и маркеры `•` → `white-space: pre-line`. |
| `speech_text` | да | **Озвучить**. Может отличаться от `display_text`. |
| `action` | да (может быть `null`) | Что делал ассистент: `create`, `list`, `search`, `update`, `delete`, `answer`, `preference`, `unknown`, `null` |
| `item` | да (может быть `null`) | Созданная / изменённая / удаляемая запись |
| `items` | только `list`, `search` | Массив найденных записей |
| `conflicts` | только при конфликте встреч | Массив `id` пересекающихся встреч |

### 4.2. Статусы и поведение интерфейса

| `status` | Когда | Что делает UI |
|---|---|---|
| `success` | Действие выполнено или список получен | Показать `display_text`. Для `create`/`update`/`delete` можно подсветить `item`; для `list`/`search` — отрисовать `items` карточками. |
| `clarification` | Не хватает данных или непонятно | Показать вопрос. **Ничего не сохранено.** Следующую фразу пользователя отправить в ту же `session_id`. |
| `confirmation_required` | Удаление, массовое удаление, конфликт встреч | Показать вопрос и кнопки **«Да» / «Нет»** — они просто отправляют текст `"да"` / `"нет"` в ту же сессию. Голосом можно ответить так же. |
| `cancelled` | Пользователь ответил «нет» | Показать текст, кнопки подтверждения скрыть. |
| `error` | Сбой LLM или базы | Показать текст красным. Действие могло не выполниться — **не писать «готово»**. Можно повторить с **тем же** `request_id`. |

Примеры из живого диалога (одна `session_id`):

```text
> Поставь встречу с Иваном послезавтра
  clarification | На какое время назначить встречу?
> в 12:00
  success/create | Встреча создана: «Встреча с Иваном» — 29.10.2026 в 12:00.

> Назначь встречу с дизайнером завтра в 15:30
  confirmation_required/create | Встреча пересекается с «Встреча с командой» (28.10.2026 в 15:00). Всё равно создать?
  conflicts: [2]
> нет
  cancelled | Хорошо, действие отменено.

> Удали встречу с командой
  confirmation_required/delete | Удалить «Встреча с командой» на 28.10.2026 в 17:00?
> да
  success/delete | Запись удалена.

> Напомни завтра в шесть позвонить сестре
  clarification | Уточни, 06:00 утра или вечера?
> вечером
  success/create | … в 18:00.
```

Выбор из нескольких записей: если под запрос подходит несколько записей, придёт `clarification` с текстом `Подходят несколько записей: 1. «…» — …; 2. «…» — … . Назови номер нужной.` Ответ — текст `"1"`, `"2"`… (можно сделать кнопки с номерами, разобрав их из текста, или просто дать ответить голосом). Для удаления после номера придёт ещё `confirmation_required`:

```text
> Удали встречу с Анной
  clarification/delete | Подходят несколько записей: 1. «Встреча с Анной» — 28.10.2026 в 10:00; 2. «Встреча с Анной» — 29.10.2026 в 11:00. Назови номер нужной. Ничего не изменено.
> 2
  confirmation_required/delete | Удалить «Встреча с Анной» на 29.10.2026 в 11:00?
> да
  success/delete | Запись удалена.
```

### 4.3. Сессия и `request_id`

- `session_id`: сгенерировать UUID при входе / кнопке «Новый диалог», хранить в `localStorage` (как сейчас делает `VoiceAssistant.newSession()`). Новый диалог **не удаляет записи**, только сбрасывает контекст («её», «эту встречу»). Состояние диалога хранится на сервере, поэтому после перезагрузки страницы с тем же `session_id` уточнение можно продолжить.
- `request_id`: новый UUID на **каждую** фразу. При сетевой ошибке/таймауте — повторить **тот же** запрос с **тем же** `request_id` (текущий `voice.js` так и делает, один повтор).
- Не отправлять следующую фразу, пока не пришёл ответ на предыдущую (флаг `busy` в `voice.js`). Сервер всё равно обрабатывает запросы одного пользователя по очереди, но параллельные фразы ломают порядок диалога.
- Таймаут ответа — закладывайте **60 секунд**: LLM иногда отвечает 10–40 с.

### 4.4. Запись (`item`, элементы `items`)

```json
{
  "id": 2,
  "type": "meeting",
  "title": "Встреча с командой",
  "start_at": "2026-10-28T15:00:00+03:00",
  "due_at": null,
  "duration_minutes": 60,
  "recurrence": null,
  "status": "pending",
  "created_at": "2026-10-27T15:03:50.403132+00:00",
  "occurrence_at": "2026-10-28T15:00:00+03:00"
}
```

| Поле | Значения |
|---|---|
| `id` | Целое, уникально в пределах пользователя |
| `type` | `task` — задача, `meeting` — встреча, `reminder` — напоминание |
| `title` | До 250 символов |
| `start_at` | Начало **встречи**; у задач/напоминаний обычно `null` |
| `due_at` | Срок **задачи/напоминания**; у встреч `null` |
| `duration_minutes` | Длительность встречи (по умолчанию 60) |
| `recurrence` | `null` или повторение, см. ниже |
| `status` | `pending` / `done` |
| `created_at` | Когда создана, UTC |
| `occurrence_at` | **Только в `list`**: дата этого конкретного повтора (для повторяющихся записей отличается от `start_at`/`due_at`). Для показа в списке используйте его. |

Поля `user_id`, `request_id`, `deleted` — служебные, на фронте не используются.

Форматы дат:
- с временем — ISO 8601 со смещением: `"2026-10-28T15:00:00+03:00"` (уже в часовом поясе пользователя, `APP_TIMEZONE`, по умолчанию Москва);
- **только дата** (время не указано) — `"2026-10-30"` → показывать «время не указано» / «весь день»;
- обе даты `null` — запись без срока.

Определить дату для отображения: `occurrence_at ?? start_at ?? due_at`; есть ли время: `value.includes('T')`.

`recurrence`:

```json
{ "freq": "weekly", "interval": 1, "by_weekday": [0, 2], "bymonthday": null, "count": null, "until": null }
```

`freq`: `daily` | `weekly` | `monthly` | `yearly`; `by_weekday`: 0 = понедельник … 6 = воскресенье; `until` — дата окончания, `count` — число повторов.

### 4.5. `list` и `search`

- `items` в `list` отсортированы по времени: до 100 записей с датой, затем — если период включает сегодня — до 20 невыполненных записей **без срока** (в `display_text` группа «Без даты»).
- Пустой результат: `items: []`, `display_text: "На выбранный период записей нет."`.
- В `search` сначала идут совпадения по словам, затем по смыслу («про презентацию» найдёт «слайды к выступлению»); поля `occurrence_at` нет.
- Если хотите рисовать карточки вместо текста — берите `items`; `display_text` всё равно стоит озвучивать/показывать как подпись.

## 5. Голосовой ввод

Два варианта, выбираются фронтом:

| | Web Speech API (браузер) | `POST /api/transcribe` (сервер, Whisper) |
|---|---|---|
| Включение | по умолчанию | `?stt=local` в адресе страницы |
| Браузеры | Chrome, Edge, Яндекс | любой с `MediaRecorder` |
| Качество русского | среднее | лучше, но медленнее |
| Сеть | звук уходит в Google/Microsoft | звук остаётся на нашем сервере |

Для обоих **нужен HTTPS** (на `localhost`/`127.0.0.1` браузер разрешает и по HTTP).

### `POST /api/transcribe`

`multipart/form-data`, поле **`audio`** — запись с `MediaRecorder` (`audio/webm`, `audio/ogg`, `audio/mp4`; тип обязан начинаться с `audio/`), **до 5 МБ**.

```js
const form = new FormData();
form.append('audio', blob, 'speech.webm');
const res = await fetch('/api/transcribe', { method: 'POST', body: form });
// 200 → { "text": "напомни завтра в десять позвонить ивану" }
```

Распознанный текст затем отправить в `/api/assistant` как обычную фразу.

| Код | `detail` | Показать |
|---|---|---|
| 200, `text: ""` | — | «Речь не распознана, повторите» |
| 400 | `empty_audio` | «Запись пустая» |
| 401 | `unauthorized` | экран входа |
| 413 | `audio_too_large` / `body_too_large` | «Слишком длинная запись» |
| 415 | `audio_required` | ошибка фронта: неверный тип файла |
| 503 | `install_faster_whisper` / `transcription_failed` | «Распознавание недоступно, напишите текстом» |

Первый запрос после запуска сервера может идти **1–2 минуты** (скачивание и загрузка модели) — таймаут на этот запрос ставьте 120 с и показывайте «Распознаю…».

## 6. Озвучивание ответа

Источник определяет `GET /api/config`:

```json
{ "tts": "browser", "auth_required": true }
```

| `tts` | Что делать |
|---|---|
| `browser` | Озвучить `speech_text` через `speechSynthesis` (как сейчас в `voice.js`) |
| `google` | Запросить аудио у сервера (ниже) и проиграть |
| `off` | Не озвучивать, скрыть галочку «озвучивать» |

### `POST /api/tts`

```json
{ "text": "Готово! Напоминание создано." }
```

Ответ — **бинарное аудио** (`Content-Type: audio/mpeg` по умолчанию; бывает `audio/ogg` / `audio/wav` — смотрите заголовок). Текст до 1000 символов.

```js
async function speakServer(text) {
  const res = await fetch('/api/tts', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ text: text.slice(0, 1000) }),
  });
  if (!res.ok) return speakBrowser(text);          // запасной вариант
  const url = URL.createObjectURL(await res.blob());
  const audio = new Audio(url);
  audio.onended = () => URL.revokeObjectURL(url);
  await audio.play();                                // ждать onended, если нужно состояние «говорит»
}
```

| Код | `detail` | Что делать |
|---|---|---|
| 404 | `tts_server_disabled` | Серверный TTS выключен — озвучить браузером |
| 413 | `text_too_long` | Обрезать до 1000 символов |
| 502 | `tts_failed: google: HTTP 403` и т.п. | Озвучить браузером, в консоль — предупреждение |

Автовоспроизведение: браузер разрешает `audio.play()` только после действия пользователя на странице (клик, нажатие клавиши) — первый запрос всё равно запускается кнопкой, так что обычно проблем нет. Перед новой фразой пользователя останавливайте текущее аудио (`audio.pause()`), как сейчас `stopSpeaking()`.

## 7. Ошибки HTTP (сводка)

| Код | `detail` | Где | Смысл → действие UI |
|---|---|---|---|
| 400 | `empty_text` | assistant, tts | Пустой текст — не отправлять пустые фразы |
| 400 | `invalid_request_id` | assistant | `request_id` длиннее 120 — ошибка фронта |
| 401 | `unauthorized` | assistant, transcribe, tts, me | Нет входа → экран входа |
| 403 | `origin_forbidden` | все POST | Страница открыта с неразрешённого адреса — ошибка конфигурации |
| 409 | `username_taken` | register | Логин занят |
| 411 | `length_required` | все POST | Нет `Content-Length` (fetch ставит сам; встречается только у самописных клиентов) |
| 413 | `body_too_large`, `text_too_long`, `audio_too_large` | все POST | Слишком большой запрос |
| 415 | `audio_required` | transcribe | Неверный тип файла |
| 422 | список ошибок валидации | все | Неверный JSON / нет обязательного поля — ошибка фронта |
| 429 | `too_many_attempts` | login | Подождать 5 минут |
| 500 | — | любой | Сбой сервера: «Что-то пошло не так, попробуйте ещё раз» |
| 502 | `tts_failed: …` | tts | Озвучить браузером |
| 503 | `transcription_failed`, `install_faster_whisper` | transcribe | Предложить текстовый ввод |
| сеть / таймаут | — | любой | Для `/api/assistant`: повторить с тем же `request_id`, затем «Сервер не отвечает. Проверьте расписание — действие могло выполниться.» |

## 8. Лимиты

| Что | Лимит |
|---|---|
| JSON-тело любого запроса | 64 КБ |
| `text` в `/api/assistant` | 8 КБ (UTF-8); ассистент разбирает до 2000 символов, длиннее — `status: error`, «Сообщение слишком длинное» |
| Аудио в `/api/transcribe` | 5 МБ |
| Текст в `/api/tts` | 1000 символов |
| `session_id` | 100 символов (длиннее — обрезается) |
| `request_id` | 1–120 символов |
| Записей в `items` | 100 с датой (+ до 20 без срока в `list`) |
| Неудачные входы | 10 за 5 минут на IP + логин |
| Жизнь сессии входа | 30 дней |

## 9. Что поменять в текущем `web/`

1. `web/index.html:92` — `apiUrl: params.get('api') || '/api/assistant'`.
2. `web/index.html:93` — убрать `userId`; в `voice.js` `_post` — убрать `user_id` из тела.
3. Экран входа: форма логин/пароль, кнопки «Войти» и «Зарегистрироваться», ошибки из §3; в шапке чата — имя пользователя (`/api/me`) и «Выйти».
4. `voice.js` `_post`: 401 → событие «нужен вход» (вместо текста про `APP_API_TOKEN`); 403 → «Страница открыта с неразрешённого адреса»; тексты про `server.py` заменить на «Сервер ассистента не отвечает».
5. `voice.js` распознавание (`listenLocal`): обработать 401 / 413 / 503 по таблице §5 вместо общего `STT: HTTP …`.
6. `voice.js` `speak()`: ветка `config.tts === 'google'` → `POST /api/tts` (§6), при ошибке — браузерный `speechSynthesis`.
7. Опция `token` в `VoiceAssistant` больше не нужна при cookie; оставить только если фронт запускается отдельно без proxy.
8. Для `list` / `search` можно рисовать `items` карточками (иконка по `type`, дата из `occurrence_at ?? start_at ?? due_at`).
9. После `/api/logout`: очистить лог чата и вызвать `assistant.newSession()`.

## 10. Проверка вручную

| Фраза | Ожидается |
|---|---|
| «Напомни мне завтра в 10 утра позвонить Ивану» | `success/create`, `item.type = reminder`, `due_at` с 10:00 |
| «В пятницу нужно отправить отчёт» | `success/create`, `due_at` — дата без времени |
| «Добавь встречу с командой завтра в 15:00» | `success/create`, `item.type = meeting`, `start_at` |
| «Поставь встречу с Иваном завтра» → «в 12» | `clarification` → (возможно «утра или вечера?») → `success` |
| Встреча на то же время | `confirmation_required`, `conflicts`, кнопки Да/Нет |
| «Что у меня сегодня?» / «Какие планы на сегодня?» | `success/list`, `items` |
| «Что запланировано на эту неделю?» | `success/list` за неделю |
| «Найди задачу про презентацию» | `success/search` — находит и по смыслу («слайды к выступлению») |
| «Удали встречу с командой» → «нет» | `confirmation_required` → `cancelled`, запись на месте |
| «А перенеси её на завтра» сразу после создания | `success/update` той же записи |
| Обновить страницу посреди уточнения и ответить | работает, если `session_id` сохранён в `localStorage` |
| Выйти, войти другим пользователем, «Что у меня завтра?» | чужих записей нет |
| Отключить сеть во время запроса | ошибка с подсказкой проверить расписание, без дубля записи после повтора |
