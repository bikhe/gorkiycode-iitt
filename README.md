# AssistantAI — голосовой помощник для задач и календаря

Рабочий прототип для командной демонстрации, версия **27.10.2026**.

## 1. Назначение и возможности

Помощник получает текст или голосовую команду, определяет действие с помощью GigaChat (Function Calling), проверяет данные на Python и сохраняет задачи, встречи и напоминания в SQLite. Результат показывает в веб-интерфейсе; при наличии рабочего браузерного TTS может произносить ответ.

Реализованные сценарии:

- создание задач, встреч, напоминаний с датой/временем;
- просмотр планов за день или период и поиск записей;
- изменение дат/времени, удаление одной записи после подтверждения;
- удаление всех записей за **конкретный день** после подтверждения; для повторяющихся серий предусмотрены ограничения;
- повторяющиеся записи (в т. ч. по дням недели), проверка конфликтов встреч;
- уточняющие вопросы при недостающей или неоднозначной информации;
- голосовой ввод через локальный **faster-whisper**, альтернативно браузерный STT, и озвучивание через браузерный Speech Synthesis.

**Статус:** функциональный прототип, не готовый к публичному развёртыванию. Понимание опечаток, разговорных имён и некоторых фраз со временем ещё не всегда надёжно. Реальная доставка уведомлений вне открытого сайта не реализована.

## 2. Архитектура

```text
Браузер: web/app/index.html (ассистент) + web/voice.js; web/index.html — лендинг
    ↓  микрофон (MediaRecorder)             ↘ текстовая команда
FastAPI: POST /api/transcribe                 POST /api/assistant
    ↓ локальный faster-whisper                    ↓
    └────────────── распознанный текст ──────────┤
                                  assistant_ai/
                              GigaChat (планировщик)
                         валидация + состояние диалога
                         поиск / CRUD / правила дат
                                      ↓
                                  SQLite
                                      ↓
                      JSON: display_text + speech_text
                                      ↓
                          Веб-интерфейс / браузерный TTS
```

`fastapi_server.py` — основной сервер. `auth.py` — вход по логину/паролю и проверки запросов. `voice_stt.py` — локальное распознавание. `voice_tts.py` — серверное озвучивание (Google). `assistant_ai/openai_planner.py` — LLM через OpenAI-совместимые API. `assistant_ai/embeddings.py` — векторы для смыслового поиска. `assistant_ai/service.py` — оркестрация, проверка и операции с записями. `dates.py`, `timeparse.py`, `timing.py` — обработка дат и времени. `gigachat_planner.py` — работа с GigaChat. `sqlite_repository.py` — локальная база. `server.py` — старый HTTP-мост, оставлен для совместимости с существующими тестами. `demo.py` — диагностическая консоль.

## 3. Системные требования

- Windows 11 или совместимая ОС; Python **3.12–3.13**, VS Code необязателен;
- доступ к GigaChat API и собственные действующие реквизиты API;
- браузер Edge/Chrome, разрешение на использование микрофона;
- интернет для вызова GigaChat и **первой загрузки** модели Whisper;
- для озвучивания — доступный браузерный голос; голос Edge/Windows может отсутствовать или выдавать `synthesis-failed`.

## 4. Установка (PowerShell, Windows)

Все команды выполняются из корня проекта (папка с `fastapi_server.py`).

```powershell
py -3.13 -m venv .venv   # или py -3.12
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если `py -3.13` не находится, проверьте `py --list` и установите подходящую версию Python. Если установка библиотек завершается ошибкой, сохраните точный вывод терминала; не заменяйте пакеты на произвольные версии без проверки совместимости.

### Настройки `.env`

Откройте созданный `.env` и заполните как минимум:

```dotenv
GIGACHAT_CREDENTIALS=ВАШ_СЕКРЕТ_ТОЛЬКО_НА_СВОЕМ_ПК
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
APP_TIMEZONE=Europe/Moscow
APP_DB_PATH=assistant_data.sqlite3
APP_CORS_ORIGIN=http://localhost:5500
APP_AUTH_REQUIRED=0
GIGACHAT_CA_BUNDLE_FILE=certs/russian_trusted_root_ca_pem.crt
```

Полный список параметров с пояснениями — в `.env.example`.

Если для TLS требуется публичный корневой сертификат GigaChat, поместите его по пути, указанному в `GIGACHAT_CA_BUNDLE_FILE`, например `certs/russian_trusted_root_ca_pem.crt`. Если системные сертификаты уже подходят, оставьте параметр пустым. **Не отключайте проверку TLS.**

**Безопасность:** настоящий `.env`, токены, рабочая база `*.sqlite3` и её `-wal`/`-shm` файлы не входят в репозиторий (закрыты в `.gitignore` и `.dockerignore`). Каждый участник создаёт свой `.env`.

## 5. Запуск — два терминала

**Терминал №1: FastAPI**

```powershell
.\.venv\Scripts\python.exe -m uvicorn fastapi_server:app --host 127.0.0.1 --port 8765
```

Проверка: откройте `http://127.0.0.1:8765/health` (ожидается `ok: true`) или `http://127.0.0.1:8765/docs` (Swagger UI).

**Терминал №2: веб-страница**

```powershell
.\.venv\Scripts\python.exe -m http.server 5500 --bind 127.0.0.1 --directory web
```

Откройте в браузере:

```text
http://localhost:5500/app/?user=demo
```

**Распознавание речи работает без интернета.** По умолчанию (`APP_STT_PROVIDER=local`) звук записывается в браузере и распознаётся на сервере локальной моделью faster-whisper; страница узнаёт режим из `GET /api/config`. Модель (`APP_STT_MODEL`, по умолчанию в `.env.example` — `small`, ~0.5 ГБ) скачивается **один раз** в фоне при первом старте сервера — для этого нужен интернет; дальше она грузится из локального кэша без обращения к сети. Распознавание одной фразы на CPU — около 3 с. Параметр `?stt=browser` в адресе включает распознавание браузера (Chrome/Edge отправляют звук на свои серверы, без интернета не работает), `?stt=local` — принудительно серверное. Озвучивание выбирает локальный голос Windows (например, Microsoft Irina) и тоже работает офлайн. Без интернета недоступен только GigaChat: для полностью офлайн-демо поставьте `APP_OFFLINE=1` (разбор фраз правилами).

FastAPI также сам раздаёт страницы: `http://127.0.0.1:8765/` — лендинг Gorky AI, `http://127.0.0.1:8765/app/` — ассистент. Второй терминал тогда не нужен, а cookie входа работает без настройки CORS.

**Вход.** Веб-интерфейс Gorky AI работает без регистрации (`APP_AUTH_REQUIRED=0` в `.env.example` и `docker-compose.yml`): браузер при первом визите получает случайный `guest-…` ID и хранит его в `localStorage`, поэтому у каждого посетителя свои записи. `?user=demo` в адресе открывает общий набор записей. Это метка данных, **не авторизация**. Если поставить `APP_AUTH_REQUIRED=1`, `/api/assistant` и `/api/transcribe` потребуют вход через `/api/register` / `/api/login` (см. раздел 7). Формы входа в `web/` нет, её нужно добавить.

**Управление записью:** первое нажатие микрофона начинает запись, повторное — завершает и отправляет аудио на расшифровку. После ответа микрофон не должен автоматически включаться. Если браузерное TTS не работает, снимите галочку «озвучивать» — текстовая часть продолжит работать.

## 6. Тестирование

Автоматические тесты:

```powershell
.\.venv\Scripts\python.exe -m py_compile .\assistant_ai\service.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют Python-логику на тестовых сценариях; они **не гарантируют** правильное распознавание голоса или стабильность живого GigaChat.

Рекомендуемые ручные проверки **сначала текстом**, затем голосом:

| Действие | Пример команды | Ожидаемое поведение |
|---|---|---|
| Создание напоминания | «Напомни завтра в 11:30 отправить документы» | Создание записи с датой и временем |
| Создание задачи | «Добавь задачу подготовить отчёт до пятницы» | Задача с дедлайном |
| Создание встречи | «Назначь встречу с Анной завтра в 16:00» | Встреча в календаре |
| Просмотр | «Что у меня завтра?» | Список за конкретный день |
| Поиск | «Найди задачу подготовить отчёт» | Найдена задача |
| Перенос | «Перенеси встречу с Анной на 30 октября в 18:00» | Изменяется существующая запись |
| Удаление | «Удали задачу подготовить отчёт» | Уточняется конкретная запись, требуется «да» |
| Отмена удаления | «Нет» | Ничего не удаляется |
| Массовое удаление | «Удали все записи на завтра» | Предварительный список/количество и подтверждение; в тесте отвечайте «нет» |
| Уточнение времени | «Напомни завтра в шесть позвонить сестре» → «Вечером» | Запись на 18:00 |

Для проверки распознавания также используйте обычные разговорные фразы, разные формы имён и опечатки — это **известная зона для развития**, а не гарантированная функция.

## 7. API

`POST http://127.0.0.1:8765/api/assistant`

Пример JSON:

```json
{
  "text": "Что у меня завтра?",
  "user_id": "demo",
  "session_id": "test-dialog-1",
  "request_id": "unique-request-001"
}
```

Ответ содержит `status`, `display_text`, `speech_text`, `action` и, в зависимости от действия, `item` / `items`. Возможные `status`: `success`, `clarification`, `confirmation_required`, `cancelled`, `error`. Для последующих уточнений **сохраняйте тот же `session_id`**, а новый запрос должен иметь новый `request_id`.

`GET /api/items` возвращает `{"items": [...]}` — все записи пользователя (`id`, `type`, `title`, `start_at`, `due_at`, `duration_minutes`, `recurrence`, `status`, `created_at`), сначала с датой по возрастанию, затем без даты. Те же проверки входа и Origin, что у `/api/assistant`; без входа владелец берётся из параметра `?user_id=`. По нему страница рисует панель «Мои записи».

`POST /api/transcribe` получает записанный аудиофайл в поле `audio` (`multipart/form-data`, до 5 МБ) и возвращает `{"text": ...}`.

Поле `user_id` учитывается только при `APP_AUTH_REQUIRED=0`; со входом владелец записей определяется по сессии.

### Вход

| Метод | Тело | Ответ |
|---|---|---|
| `POST /api/register` | `{"username", "password"}` | `{"user", "token"}` + cookie; 409 — логин занят, 400 — логин/пароль не подходят |
| `POST /api/login` | `{"username", "password"}` | `{"user", "token"}` + cookie; 401 — неверно, 429 — больше 10 ошибок за 5 минут |
| `POST /api/logout` | — | `{"ok": true}`, сессия удаляется |
| `GET /api/me` | — | `{"user": {"id", "username"}}` или 401 |

Логин: 3–32 символа (латиница, цифры, `_ . -`), пароль: 8–128 символов. Сессия живёт 30 дней. Токен передаётся HttpOnly-cookie `assistant_session` (страница с того же адреса) или заголовком `Authorization: Bearer <token>`.

Коды ошибок сервера: 401 — нет входа, 403 — запрос со стороннего сайта (`origin_forbidden`), 411/413 — нет длины тела или тело слишком большое (JSON до 64 КБ).

## 7a. Деплой на VPS (Docker)

Нужны: сервер с Docker, домен с A-записью на сервер, открытые порты 80/443, 3 ГБ RAM и ~3 ГБ диска (Whisper `small` + модель эмбеддингов mpnet; с Whisper `base` и MiniLM хватит 1.5 ГБ RAM). Модели скачиваются при первом запуске в том `app-data`.

```bash
git clone <репозиторий> && cd <папка>
cp .env.example .env                       # заполнить GIGACHAT_CREDENTIALS
DOMAIN=assistant.example.ru docker compose up -d --build
```

Проверка после запуска:

```bash
docker compose ps                          # app — healthy, caddy — running
docker compose logs -f app                 # первая загрузка моделей — несколько минут
curl https://$DOMAIN/health                # {"ok":true,...}
```

Обновление: `git pull && DOMAIN=... docker compose up -d --build`. Записи в томе `app-data` сохраняются.

Caddy автоматически получает HTTPS-сертификат — без HTTPS браузер не даст доступ к микрофону. Сайт: `https://<DOMAIN>/` (лендинг), ассистент: `https://<DOMAIN>/app/?stt=local`. База и кэш модели Whisper лежат в томе `app-data` и переживают пересборку. Сервер работает в одном процессе (`--workers 1`): SQLite и блокировки пользователей рассчитаны на это.

Полное описание API для фронтенда (вход, статусы диалога, голос, ошибки, что поменять в `web/`) — в [FRONTEND.md](FRONTEND.md).

## 7c. Провайдеры LLM и озвучивания

**LLM** (`APP_LLM_PROVIDER`) только разбирает запрос в структуру `plan_action`; проверка дат и работа с базой одинаковы для всех провайдеров, системный промпт общий (`gigachat_planner.system_prompt`).

| Значение | Адрес | Что задать |
|---|---|---|
| `gigachat` (по умолчанию) | SDK GigaChat | `GIGACHAT_CREDENTIALS` |
| `openai` / `deepseek` / `openrouter` / `yandex` / `ollama` | пресет в `openai_planner.PRESETS` | `LLM_MODEL`, `LLM_API_KEY` (для Ollama не нужен) |
| `openai_compatible` | `LLM_BASE_URL` | `LLM_MODEL`, при необходимости `LLM_API_KEY` |
| `rules` | — | без LLM, базовые фразы (то же, что `APP_OFFLINE=1`) |

Модель должна поддерживать tools / function calling. Проверен вживую только GigaChat; остальные — тестами на формат запросов и ответов (`tests/test_providers.py`). Для YandexGPT `LLM_MODEL` имеет вид `gpt://<folder_id>/yandexgpt/latest`. Провайдер с другим API — новый класс с методом `plan(text, context, now, catalog) -> dict` и ветка в `factory.make_planner`.

**Озвучивание** (`APP_TTS_PROVIDER`): `browser` (по умолчанию, озвучивает фронт), `google`, `off`.

- `GET /api/config` → `{"tts": "browser" | "google" | "off", "auth_required": bool}` — по нему фронт решает, озвучивать ли самому.
- `POST /api/tts` с `{"text": "..."}` → аудио (`audio/mpeg` для MP3), до 1000 символов; те же проверки входа и Origin, что у `/api/assistant`. 404 — серверный TTS выключен, 502 — ошибка провайдера (без деталей ключа).

Google: в Google Cloud включить «Cloud Text-to-Speech API», создать API key, ограничить его этим API и записать в `GOOGLE_TTS_API_KEY`. Ключ остаётся на сервере и в браузер не попадает. Интеграция проверена тестами на формат запроса; на живом ключе — **ещё нет**. Новый провайдер TTS — класс с `synthesize(text) -> (bytes, mime)` и ветка в `voice_tts.make_tts`.

## 7b. Поиск

Сначала поиск по словам (основы слов + словарь синонимов), затем по смыслу через эмбеддинги. Векторы хранятся в SQLite вместе с именем модели и пересчитываются при переименовании записи или смене модели.

Источник эмбеддингов — `APP_EMBEDDINGS`:

| Значение | Что используется | Примечание |
|---|---|---|
| `local` (по умолчанию) | `paraphrase-multilingual-mpnet-base-v2` через fastembed (ONNX, без torch) | ~1 ГБ, скачивается один раз в `FASTEMBED_CACHE_PATH`; дальше работает без интернета. Грузится в фоне при старте — до готовности поиск идёт по словам. Для слабого сервера: `APP_EMBEDDINGS_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (~0.2 ГБ) |
| `gigachat` | GigaChat `Embeddings` | Нужен тариф с эмбеддингами; на 402/403 вызовы отключаются на час |
| `off` | только поиск по словам | |

Смысловое совпадение показывается, если сходство не ниже порога модели **и** не дальше 0.08 от лучшего совпадения: одного порога мало, «презентация» похожа и на «отчёт». Пороги подобраны на запросах из ТЗ: mpnet — 0.6, MiniLM — 0.55; на контрольных запросах («погода в Москве», «рецепт борща») ложных совпадений нет. Переопределить — `APP_SEMANTIC_THRESHOLD`. Проверка на живой модели:

```powershell
$env:APP_TEST_LOCAL_EMBEDDINGS='1'; .\.venv\Scripts\python.exe -m unittest tests.test_fastapi.LocalModelTests -v
```

## 8. Известные ограничения (для честной демонстрации)

1. Не все опечатки Whisper, уменьшительные имена и синонимы корректно распознаются. Например, «Аннушка» не всегда связывается с записью «Анна»; неоднозначную цель лучше уточнять.
2. Разговорные часы 1–12 могут относиться к утру или вечеру. Неоднозначное время нужно уточнять; в отдельных фразах ассистент ещё может ошибаться.
3. Автоматической доставки напоминаний, когда приложение закрыто, нет. Система **хранит** напоминания.
4. Повторяющиеся серии поддерживаются с ограничениями; удаление одной записи из серии не равно удалению всей серии.
5. Браузерная озвучка зависит от голосов Edge/Windows и может возвращать ошибку `synthesis-failed`.
6. Вход по логину и паролю есть, но без подтверждения почты и восстановления пароля; ограничение попыток входа хранится в памяти процесса.
7. Данные SQLite сохраняются между запусками. Кнопка «Новый диалог» обновляет контекст, но не очищает базу.

## 9. Возможные ошибки

- **`ModuleNotFoundError`**: убедитесь, что зависимости установлены через `.venv` и команды выполняются из корня проекта.
- **Ошибка сертификата / GigaChat**: проверьте `GIGACHAT_CREDENTIALS`, выбранную модель и путь `GIGACHAT_CA_BUNDLE_FILE`. Не публикуйте содержимое `.env`.
- **CORS / 403**: настройте `APP_CORS_ORIGIN=http://localhost:5500` и перезапустите FastAPI.
- **`POST /api/transcribe` 503**: проверьте установку `faster-whisper` / PyAV, загрузку модели и traceback FastAPI. Сообщение `metadata_errors` означает несовместимую версию PyAV: нужна `av<17` (см. `requirements.txt`, проверена 16.1).
- **Микрофон не работает**: разрешите доступ к микрофону в браузере, используйте `localhost` или `127.0.0.1` (на других адресах нужен HTTPS).
- **Нет озвучки**: проверьте галочку, системный звук и список установленных голосов. Текстовые запросы продолжают работать без TTS.
- **Отображаются старые тестовые записи**: они лежат в SQLite. Не удаляйте базу, если важно сохранить результаты; для изолированного стенда используйте новый локальный `APP_DB_PATH`.

## 10. Передача проекта и дальнейшая интеграция

Передавайте **исходный код**, `requirements.txt`, `README.md`, `.env.example` и тесты. Не передавайте `.env`, `.venv`, приватные сертификаты, SQLite с личными тестовыми данными и файлы WAL/SHM.

В следующем этапе можно добавить: нормализацию опечаток и синонимов, сопоставление уменьшительных имён с подтверждением, более устойчивое запоминание цели при уточнениях, надёжную обработку 12-часового времени, отдельный TTS-движок, авторизацию пользователей и фоновую доставку уведомлений.

**Зафиксированная версия — прототип на дату 27.10.2026.** Изменения после передачи лучше вести в отдельной ветке/копии, чтобы не сломать рабочую демонстрацию.
